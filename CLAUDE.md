# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A TypeScript library to calculate, validate, and decode Italian Fiscal Codes (Codice Fiscale). Published to npm as `codice-fiscale-ts`, shipped as dual CJS/ESM with tree-shaking. The headline feature is auto-updated municipality data sourced from ISTAT and the comuni-json repo.

## Commands

Tooling runs on **Bun** (see `bun.lock`; the pre-commit hook runs `bun run lint` + `bun test`). Bun executes TS directly, so scripts need no transpile step.

```bash
bun test                       # run all tests (bun's runner; test files use node:test APIs)
bun test src/__tests__/codiceFiscale.test.ts   # run a single test file
bun run test:watch             # watch mode
bun run test:coverage          # coverage -> ./coverage (text + lcov)
bun run type:check             # tsc --noEmit
bun run lint                   # biome check (lint + format + imports; warnings are errors)
bun run build                  # tsdown: dual CJS/ESM + .d.mts/.d.cts into ./build
bun run update-and-commit      # refresh src/data/municipalities.ts from upstream APIs and commit
```

## Architecture

Everything lives in `src/`. The public API surface is re-exported from `src/index.ts` — add new exports there.

- **`src/codiceFiscale.ts`** — all calculation/decoding/validation logic (name codes, year/month/day-gender codes, check character, `calculateFiscalCode`, `decodeFiscalCode`, `isValidFiscalCode`, place↔code lookups).
- **`src/types.ts`** — types **and** runtime type guards (`isItalianPerson`, `isForeignPerson`, `validatePerson`). A `Person` is a discriminated union: `ItalianPerson` (has `birthPlace`, `foreignCountry` only `'IT'`/undefined) vs `ForeignPerson` (has `foreignCountry` alpha2, `birthPlace: never`). Most logic branches on these guards.
- **`src/data/municipalities.ts`** and **`src/data/countries.ts`** — large generated data tables as tuple arrays (`Municipality = [code, name, province]` or bilingual 5-tuple; `Country = [cadastralCode, alpha2]`). **Do not hand-edit `municipalities.ts`** — it is regenerated by `scripts/update-municipalities.ts`.

### Tree-shaking constraint (important)

The data files are loaded via **dynamic `import()`** inside the functions that need them (see `getMunicipalityByCode`, `getMunicipalities`, `getForeignCountries`). This is deliberate: it keeps the ~8000-line municipality table out of the bundle for users who only call `isValidFiscalCode` (which is sync and pulls in no data). Preserve this pattern — never add a top-level static import of `./data/municipalities.ts` from code reachable by the validation path, or you break the "validate-only is <10kB" guarantee. Functions that touch place data are consequently `async`.

### Country codes

Foreign people use **ISO 3166-1 alpha-2** codes (not Italian country names), mapped to cadastral `Z###` codes via `countries.ts`.

## Build pipeline (`tsdown.config.ts`)

tsdown (Rolldown) bundles `src/index.ts` to ESM (`.mjs`) and CJS (`.cjs`), minified, with code splitting in both formats so the data tables stay in lazily loaded chunks, and emits `index.d.mts`/`index.d.cts`. Every build also runs publint and arethetypeswrong; fix any issue they report before releasing. Only `build/` is published (`files` in package.json).

## Release

semantic-release runs in `.github/workflows/codice-fiscale-ts.yml` on Node 24, publishing via npm trusted publishing (OIDC, no token). It is the only workflow allowed to publish: `update-municipalities.yml` pushes new data and then dispatches it.

## Conventions

- Formatting/linting via **Biome** (`biome.json`): single quotes, semicolons, 2-space indent, 80 col, no trailing commas. `noExplicitAny` and `noUnusedVariables`/`noUnusedImports` are errors. `src/data/` is excluded: its format must match what `scripts/update-municipalities.ts` generates.
- Imports use explicit `.ts` extensions (`allowImportingTsExtensions`, bundler resolution).
- Commits go through **commitizen** (`bun run cz`) — conventional commits drive `semantic-release`. Don't write release-shaped commit messages by hand if you intend a release.
- Every exported function carries TSDoc with an `@example`; match that when adding functions.
